# Contribuindo com o Forge

## Organização e nomes

Mantenha cada conteúdo na área correta, com nomes em minúsculas e separados por hífen. Documente estudos no respectivo `README.md`, incluindo objetivo, referências, dúvidas e como executar quando aplicável.

## Branches e commits

Crie branches como `study/php-introducao`, `study/php-poo`, `study/mysql-introducao`, `study/symfony-services`, `study/vue-componentes`, `docs/arquitetura-hexagonal` ou `challenge/php-testes`.

Use Conventional Commits, por exemplo:

- `feat: adiciona exercício de orientação a objetos`
- `docs: adiciona anotações sobre arquitetura hexagonal`
- `test: adiciona testes com PHPUnit`
- `refactor: reorganiza exemplos de PHP`
- `fix: corrige configuração de teste`
- `chore: atualiza estrutura do repositório`

## Qualidade e Pull Requests

Execute os testes disponíveis antes de abrir um Pull Request e solicite revisão de código quando houver código executável.

### Checklist para Pull Request

- [ ] O conteúdo está na pasta correta
- [ ] O README foi atualizado
- [ ] O código está legível
- [ ] Os testes foram executados
- [ ] Nenhuma credencial foi adicionada
- [ ] O objetivo do estudo está documentado
- [ ] As referências foram informadas

## Segurança

Nunca envie materiais confidenciais da empresa, código-fonte interno, nomes de clientes, URLs internas, tokens, senhas, credenciais, dados pessoais, prints de sistemas internos ou documentos internos não autorizados. Arquivos `.env` e segredos devem permanecer fora do Git.
