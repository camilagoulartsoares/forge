# Projetos

- **Desafios:** problemas delimitados para prática.
- **Estudos:** investigações focadas em um tema.
- **Provas de conceito:** validações pequenas de viabilidade técnica.
- **Projetos completos:** aplicações com escopo, documentação e qualidade definidos.

## Como delimitar uma entrega

Escolha a categoria pelo objetivo: investigar uma dúvida cabe em estudos;
validar uma hipótese técnica cabe em POC; resolver um enunciado cabe em desafios.
Reserve projetos completos para um fluxo de uso com começo, meio e fim.

Antes de implementar, registre no README do projeto:

- Problema, público do exercício e um cenário de uso verificável.
- Escopo incluído e funcionalidades adiadas.
- Pré-requisitos, preparação local e comandos de execução.
- Critérios de aceitação com entradas e resultados esperados.
- Verificações realizadas e limitações conhecidas.

Exemplo de critério: ao cadastrar uma tarefa com título vazio, o sistema deve
recusar a entrada e manter a lista anterior. Uma POC também deve registrar
se a hipótese foi confirmada, rejeitada ou ficou inconclusiva, com a evidência.

Para integrar os exemplos da trilha, pratique o [desafio de lista de tarefas](desafios/lista-de-tarefas.md),
com critérios para consulta, erro, pesquisa, ordenação e navegação.
